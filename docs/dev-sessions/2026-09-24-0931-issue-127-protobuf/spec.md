# Protocol Buffers wire format Spec

**Goal:** Replace gob (Unix socket) and the JSON envelope (WebSocket) with one
protobuf schema, so the wire format has a single source of truth, pane grids
shrink, and the browser client works on generated, typed messages.

**Source:** #127. Supersedes PR #144, which was written against a pre-#163/#165
message set; this redoes it from main 0af1782 as a new PR, reusing what still fits.

## Current state

See `research.md`. Load-bearing facts:

- 15 message types cross the transport (research §1): 10 client→server, 5
  server→client. #165 added `MsgPanePatch`/`PaneRow`/`MsgPaneResync` and
  `MsgPaneUpdate.Generation uint64`; #163 removed `MsgFocusPane`, added
  `MsgVerb.PaneID` and `MsgPaneCreated`, and made `PaneStatuses map[int]PaneStatus`.
- Socket: gob, all types registered, no direction filter (socket.go:69-88).
- WebSocket: JSON `{t,p}`, outbound by reflected type name, inbound via the
  `clientTypes` allowlist (websocket.go:113-123), plus #164's ping/pong,
  deadlines, 1 MiB read limit and slow-peer close.
- Web: `client.ts` hands untyped `{t,p}` to an if/else in `wideboi-app.ts:258-284`;
  the renderer, focus, colors and input modules use hand-written PascalCase
  types in `protocol.ts`.

## Desired end state

- `internal/protocol/wirepb/wideboi.proto` defines every wire message, with
  `ClientMessage` / `ServerMessage` oneof envelopes. Go and TS bindings are
  generated by `make proto` (`buf generate`) and checked in.
- `internal/protocol/codec.go` provides `MarshalClient`/`UnmarshalClient`/
  `MarshalServer`/`UnmarshalServer` between the existing Go structs and the
  generated types. Unknown types are errors.
- Unix socket: 4-byte big-endian length-prefixed protobuf frames, 64 MiB cap.
- WebSocket: one binary protobuf message per frame. All #164 behaviour
  (ping/pong, deadlines, 1 MiB read limit, slow-peer close) is unchanged.
- Web: `WideboiClient.onMessage` receives a generated `ServerMessage`;
  `send()` takes a typed `ClientMessage` oneof value. `wideboi-app.ts`
  switches on `msg.case`; the renderer, focus, colors and input modules use
  generated types. `protocol.ts` keeps only client-local types (placement,
  rectangle, layout mode).
- `make check` runs the web tests (`web-test`) as well.

## Design decisions

- **Go keeps its own structs; the codec converts at the transport edge.**
  - **Why:** the patch code relies on value copies and `==` on `CellData`
    (pane_patch.go `next := base`, `slices.Equal`), which generated messages
    don't support. Using them would put `proto.Equal` and a heap allocation per
    cell on the per-frame render path, and churn server/client/tests just
    rewritten by #163/#165.
  - **Rejected:** generated structs everywhere (#127 step 2). The PR says it
    diverges from #127 here and why.
- **An exhaustive reflection test guards the codec** — the agreed compromise
  for not converting the Go side (Les, 2026-09-24). It fills every exported
  field of every wire type with non-zero values, round-trips it, and requires
  `reflect.DeepEqual`. A field the codec forgets fails the build. This closes
  the codec's main long-term risk: a field added in Go but silently dropped on
  the wire.
- **Enum values are pinned by test.** The codec casts `VerbType`, `MouseKind`,
  `ColorKind` and `PaneStatus`; a table test checks each Go constant against its
  generated value, plus the counts (carried over from #144's fix commit).
- ~~**Generation fields use `[jstype = JS_NUMBER]`.**~~ **Superseded in
  phase 1:** protobuf-es ignores `JS_NUMBER`, so generations are `bigint` in
  the browser. That is safe because bigint compares by value and TypeScript
  rejects mixing it with number. See `notes.md`.
- **Typed messages throughout the web client** (Les, 2026-09-24). protobuf-es
  v2 messages are plain objects, so they work as the app's own types. The
  renderer reads `lines[y].cells[x]` and must treat a missing `style` or
  colour as the zero value, because the codec omits zero-valued sub-messages.
- **On the wire, absence always means zero, never "unchanged".** This holds
  because patches are row-granular: a `PaneRow` replaces a whole row, and a
  patch's cursor/mouse fields overwrite unconditionally (pane_patch.go:36-56,
  renderer.ts:84-111). Proto3 omits zero scalars, so a patch that hides the
  cursor carries no `cursorVisible` at all and must decode as "set false".
  A test covers that case through the codec (Go) and `handlePanePatch` (web).
  Any future field-level delta would need explicit presence (`optional`);
  the proto file says so in a comment.
- **Truncated socket frames count as a clean close.** Keep
  `io.ErrUnexpectedEOF` in `isCleanClose`: server shutdown closes conns from
  outside the write pump, so a frame can be cut off. A whole frame that won't
  decode is still an error (tested). Carried over from #144's fix commit.
- **WebSocket inbound: undecodable → warn and skip; a non-binary frame → warn
  and skip.** Same as main's unknown-type handling. The connection stays up.
- **`MsgStatusRequest` is accepted over WebSocket.** The codec decodes every
  client type; it is read-only (triggers a snapshot). Main's allowlist
  omitted it only because the web client never sends it.
- **No cross-version compatibility.** gob had none either; the browser is
  served by the same binary. Field numbers start fresh; nothing is reserved.
- **Frame writes: header and payload in one `Write`.** One syscall per
  message on the pane-update path (a #144 review nit, applied here).

## Patterns to follow

- Reuse from PR #144 (branch `issue-127-codex`): `frame.go` + `frame_test.go`,
  `buf.yaml`, `buf.gen.yaml`, Makefile `proto`/`web-test` targets, README
  section, `codec.go` and `wideboi.proto` as starting points, `codec_test.go`
  enum test, and the size test (protobuf grid ≥3× smaller than JSON).
- Pump structure stays as on main: socket.go writeLoop/readLoop and `connErr`
  (socket.go:29-67, 203-414); websocket.go pumps (websocket.go:59-214).
- Resync flow unchanged: renderer returns false → app sends `MsgPaneResync`
  (wideboi-app.ts:276-279, renderer.ts:84-111).
- Keep `internal/protocol/wire_test.go` (`wireTypes`, no-interfaces) — it
  checks the Go structs, which remain the in-process model.

## What we're NOT doing

- Replacing Go structs with generated types in server/client/layout.
- Changing `InProcChannel` or any in-process message passing.
- Changing `wideboi status --json` output (Go json on the struct, status.go:43-46).
- Adding a `MsgPaneClosed` producer or Go client handling (research: none exists).
- Protocol versioning, schema-evolution rules, or `buf breaking` in CI.
- Changing token auth, the `/ws` handshake, or #164's pump behaviour.
- Renderer behaviour or visual changes beyond the type migration.
- #144's other nits (web console logging, `wire.go` comment layout) except
  where the rewritten code naturally covers them.
